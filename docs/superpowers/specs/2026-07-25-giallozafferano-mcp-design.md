# GialloZafferano MCP 设计规格

## 目标

构建一个基于 TypeScript 和 Node.js 的 MCP Server，按需读取 [GialloZafferano 英文站](https://www.giallozafferano.com/) 的公开内容。服务器覆盖菜谱、专题、文章、视频和作者等内容，不建立整站镜像，也不提供任意网站抓取能力。

成功标准：

- MCP 客户端可搜索官网公开的菜谱索引，并读取搜索结果中可识别的内容类型。
- 客户端可按 URL 获取菜谱、文章、视频、作者和其他专题页的结构化数据。
- 所有结果都包含原始来源 URL，便于核验。
- 外部请求具有域名限制、超时、限速、响应体积限制和可操作的错误信息。
- 核心解析逻辑可通过本地 fixture 稳定测试，默认测试不依赖实时网站。

## 范围

### 包含

- 实时读取 `giallozafferano.com` 的公开网页。
- 使用站内搜索发现内容。
- 优先解析页面中的 JSON-LD，缺失字段通过 HTML 选择器补齐。
- 以统一 JSON 返回内容元数据和正文数据。
- 进程内短期缓存重复请求。

### 不包含

- 登录、账户、评论、收藏或其他用户操作。
- 整站抓取、持久化镜像或长期内容数据库。
- 绕过验证码、访问限制、付费墙或 robots 策略。
- 默认使用 Playwright 等无头浏览器执行页面 JavaScript。
- 访问 GialloZafferano 之外的 URL。

## 技术方案

采用「站内搜索 + 结构化数据优先解析」。详情页首先提取 JSON-LD 中的 `Recipe`、`Article`、`VideoObject` 或 `Person`。当结构化数据缺少已知字段时，再通过页面选择器补齐。

纯 HTML 解析不作为主路径，因为它更易受页面改版影响。无头浏览器不进入第一版，因为它会显著增加启动时间、依赖体积和部署复杂度。必须执行 JavaScript 才能读取的页面将返回明确的不支持信息和原始来源链接。

## 架构

```text
MCP Client
    |
    v
Tool handlers -> Content services -> Search / typed parsers
                                      |
                                      v
                              Restricted HTTP client
                                      |
                                      v
                            giallozafferano.com
```

模块职责：

- `src/server.ts`：创建 MCP Server、注册工具并连接 stdio transport。
- `src/client/`：域名白名单、HTTP 请求、超时、有限重试、限速、缓存、User-Agent 和响应体积限制。
- `src/search/`：解析站内搜索结果，统一内容类型、标题、摘要、图片和来源 URL。
- `src/parsers/`：按内容类型解析 JSON-LD，并在必要时使用 HTML 回退。
- `src/tools/`：定义 Zod 输入 Schema，调用业务模块并格式化 MCP 响应。
- `tests/fixtures/`：存放经过精简的 HTML 样本，不保存无关页面内容。

MCP 注册层不包含页面解析细节。HTTP 客户端、搜索解析器和各类型解析器均可独立测试。

## MCP 工具

### `search_content`

搜索官网公开的菜谱索引，并对结果中的内容类型进行归一化。官网搜索页主要提供菜谱发现；其他类型通过已知 URL 调用对应详情工具。

输入：

- `query`：必填搜索词。
- `content_type`：可选枚举，支持 `all`、`recipe`、`article`、`video`、`author` 和 `collection`，默认 `all`。
- `limit`：可选，默认 10，范围为 1 到 20。

输出包含内容类型、标题、摘要、缩略图和来源 URL。搜索结果不自动读取每个详情页。

### `get_recipe`

读取菜谱名称、描述、图片、份数、准备时间、烹饪时间、总时间、难度、食材与用量、步骤、营养信息、作者和来源 URL。页面未提供的字段返回 `null` 或空数组，不推测缺失信息。

### `get_article`

读取文章标题、摘要、正文、作者、发布日期、修改日期、图片、相关内容和来源 URL。

### `get_video`

读取视频标题、描述、缩略图、时长、上传日期、作者、嵌入信息和原始播放页 URL。工具不下载视频文件。

### `get_author`

读取作者名称、简介、头像、公开个人页信息和页面列出的内容摘要。

### `get_page`

读取不属于上述类型的站内专题或集合页，返回标题、描述、主要正文、可识别的内容链接和来源 URL。该工具不是通用网页抓取器。

所有详情工具只接受 HTTPS 且主机名为 `giallozafferano.com` 或其明确允许的子域名的 URL。禁止用户信息、内网地址、重定向到外站的目标和非 HTTP(S) 协议。

## 数据流

1. MCP 工具使用 Zod 校验参数。
2. URL 校验器规范化 URL，并检查协议、主机名和凭据字段。
3. 进程内缓存命中时直接返回已解析结果。
4. 限速器允许请求后，HTTP 客户端发起带超时的请求。
5. 客户端校验每次重定向的目标域名、状态码、内容类型和响应体积。
6. 解析器提取并验证 JSON-LD；必要时使用 HTML 选择器补齐字段。
7. 业务层返回稳定的类型化对象。
8. 工具处理器输出结构化 JSON，并始终保留来源 URL。

缓存仅存在于当前进程，使用较短 TTL 和有限容量。它用于合并重复请求，不作为内容存储或离线索引。

## 错误处理

所有外部调用均被捕获，MCP 错误响应设置 `isError: true`，并提供下一步建议。错误分为：

- 参数错误：缺少搜索词、超出数量范围或 URL 格式无效。
- 安全拒绝：URL 不属于允许域名，或重定向离开允许域名。
- 内容不存在：HTTP 404 或页面已删除。
- 上游限制：HTTP 403、429 或明确的访问挑战。
- 暂时故障：网络超时、连接失败或上游 5xx。
- 类型不匹配：详情工具收到不属于目标类型的页面。
- 解析失败：页面可访问，但关键结构无法识别，提示网站结构可能已变化。

仅对幂等 GET 请求进行有限重试。429 响应遵守合理的 `Retry-After`，但不会长时间阻塞 MCP 调用。

## 安全与合规

- 网络访问采用严格域名白名单，并逐次检查重定向，防止 SSRF。
- 限制并发数、请求频率、超时时间和最大响应体积。
- 不执行网页脚本，不下载视频，不提交表单。
- 不记录完整网页正文或敏感请求信息。
- 使用清晰的 User-Agent 标识客户端用途，并遵守站点公开访问限制。
- 输出保留来源链接，不声称拥有或重新发布网站内容。

## 测试策略

### 单元测试

- 每种 JSON-LD 类型的正常解析和字段缺失路径。
- HTML 回退选择器。
- 搜索结果解析、去重、类型归一化和数量限制。
- URL 域名、协议、凭据、子域名和重定向校验。
- 缓存过期与容量边界。

### 集成测试

- 通过 MCP SDK 的内存 transport 列出并调用全部工具。
- 模拟成功、404、403、429、5xx、超时、超大响应和错误内容类型。
- 验证错误均返回 `isError: true`，且 stdio 不被调试日志污染。

### 实时冒烟测试

提供单独命令，对少量公开页面执行只读验证。该测试默认关闭，不作为 CI 成功条件；它用于发现网站结构变化。

## 分发与运行

- 运行环境为 Node.js 20 或更高版本。
- 使用 `@modelcontextprotocol/sdk`、Zod 和成熟的 HTML 解析库。
- 构建产物通过 stdio 启动，可在 Codex、Claude Desktop 或其他 MCP 客户端中配置。
- README 提供安装、构建、测试、客户端配置和实时冒烟测试说明。

## 验收标准

- 所有 6 个工具可通过 MCP Client 列出，输入 Schema 和描述完整。
- fixture 测试覆盖各内容类型的正常与失败路径。
- 非允许域名及外站重定向在发起后续请求前被拒绝。
- 上游故障不会导致服务器进程崩溃或污染 stdio。
- 搜索与详情结果均包含可核验的 GialloZafferano 来源 URL。
- 默认测试在无网络环境下可以稳定运行。
